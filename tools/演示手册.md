**操作**：点击页面顶部「FRR 真实拓扑」tab，点「立即刷新」。

## 3. 场景三：Agent 故障演练（2 分钟）—— 展示 "AI 驱动运维闭环"

**操作**：切回「对话诊断」tab，输入下面这段话并发送：

> 在 frr1 上做一次真实故障演练：先用 frr_fault_inject status 看基线，然后 inject link_down（iface=eth0），取证确认 OSPF 邻居消失，最后 recover 恢复并复验

**真实效果**（约 30-60 秒，页面流式输出）：



1. Agent 调用 `frr_fault_inject action=status` → 返回 OSPF 邻居正常（2.2.2.2 Full）

2. Agent 调用 `action=inject fault=link_down iface=eth0` → 真实执行 `docker exec frr1 ip link set eth0 down`

3. Agent 调用 `action=show show ip ospf neighbor`（走 docker exec 带外通道）→ 返回 "无邻居"—— 故障已生效

4. **此时切到拓扑页看效果**：frr1 变红 / 灰色，链路断开，路由表里的 OSPF 路由消失

5. 切回对话，Agent 调用 `action=recover` → 恢复 eth0

6. 回到拓扑页点「立即刷新」→ 节点恢复绿色、路由恢复

**讲给面试官的话**（这个环节是面试核心，讲透三点）：



* **为什么用 docker exec 带外恢复**：" 真实网络里 `shutdown` 接口会连管理面一起切断（SSH 就断了）。所以我设计了双通道模型：读状态走 SSH 业务通道，注入 / 恢复故障走 docker exec 带外通道 —— 类比机房里的 console 口 / ILO 远程管理卡。这是真实运维设计，不是玩具。"

* **为什么 Agent 能自己闭环**："ReAct 循环 —— 模型每次决策都基于上一步工具的真实返回，先取证再下结论，最后强制恢复。恢复是幂等的，最坏情况页面上一键恢复兜底。"

* **故障可逆**："演练不会弄坏环境，这是面试官最担心的点。"

**如果面试官想看更多故障**（可选，任一）：



* `在 frr2 上把 eth1 的 BGP 邻居断开演练一次` → eBGP 掉、frr3 路由表变化

* `在 frr1 上演练 ospf_cost` → 改 OSPF 开销，路由选路变化

## 4. 翻车预案（提前记住，别现场慌）



| 现象                | 原因              | 处理                                        |
| ----------------- | --------------- | ----------------------------------------- |
| 对话不回复 / 报 API 错误  | 智谱 API 欠费 / 网络断 | 检查联网；换问题重试；对话功能非核心，直接跳到拓扑页                |
| 拓扑页节点灰色           | 容器没起来 / 刚拉起     | 等 30 秒自动刷新；点「立即刷新」；再不行双击启动器               |
| 页面打不开             | 后端挂了            | 双击启动器（会自愈）                                |
| Agent 中间报 "设备不可用" | 模型试图连仿真设备（已硬拦截） | 这是设计好的防护，可顺势讲："看，模型想乱连设备，工具层把它拦住了"—— 反而加分 |
| 演练后设备还是红的         | 恢复步骤被模型跳过       | 点页面「一键恢复」按钮（admin 幂等兜底）                   |

**终极底线**：所有环节都不行时，双击启动器 → 打开拓扑页 → 讲 "这是一套真实 FRR 协议栈 + RAG 知识库 + ReAct Agent 的完整系统"，依然成立。容器协议收敛 40 秒，等得起。

## 5. 面试问答速查（被追问时）



* \*\*" 路由表里 O>` 是什么意思？"** → O = OSPF 路由，`\*\` = 活跃路由，\[110/10] = 管理距离 110 /metric 10

* **"为什么用 FRR 不用华为模拟器？"** → FRR 是生产级开源路由软件（很多厂商用它做数据面），比模拟器更接近真实；且 docker 容器化可复现、可讲原理

* **"RAG 知识库里有什么？"** → 网络运维手册 / 排障案例，119 个知识块，用户提问时语义检索 + 向量化

* **"为什么不用 LangChain？"** → 自研 ReAct 循环几百行，每步可控可讲，面试能说清 Agent 原理（工具注册、意图路由、RBAC、硬约束守卫）

* **"模型是什么？"** → 智谱 GLM（对话 glm-4-flash，嵌入 embedding-3），后端 .env 配置，可换任何 OpenAI 兼容模型

* **"项目里最难的点？"** → ①双通道运维模型（业务面 / 带外分离）②Agent 幻觉防护（提示词软约束 + 工具层硬约束双层拦截）③启动器自愈（后端挂了自动拉起）
