# 交换机堆叠 iStack 故障排查

## 问题现象
堆叠成员交换机之间堆叠链路中断导致分裂（split-brain），成员各自独立工作、业务中断；或堆叠系统反复主备切换、堆叠口 up/down 抖动。

## 排查步骤
1. 查看堆叠状态：
   ```
   display stack
   display stack configuration
   ```
   - 确认各成员的角色（Master/Standby/Slave）与堆叠拓扑（链形/环形）；
   - 环形拓扑必须所有堆叠口都 up，任意一个断开拓扑会退化。

2. 检查堆叠口与堆叠线缆：
   - 堆叠口物理状态、光模块/堆叠线缆是否松动；
   - 堆叠链路质量差（误码）会导致分裂和频繁倒换。

3. 检查堆叠参数一致性：
   ```
   display stack peer-link
   ```
   - 成员优先级、域编号（domain）、系统 MAC 竞争；
   - 成员交换机软件版本必须一致（版本不一致会导致加入失败）。

4. 处理分裂场景：
   - 分裂后两台设备以相同优先级竞争，容易"脑裂"；
   - 配置 MAD（多活检测，通过堆叠口/业务口检测）来检测并关闭备用侧业务口。

5. 查看日志确认倒换原因：
   ```
   display logbuffer | include STACK|MAD
   ```

## 常见根因与处置
| 根因 | 处置 |
|---|---|
| 堆叠线缆/光模块故障 | 更换堆叠线缆，恢复环/链拓扑 |
| 软件版本不一致 | 升级到统一版本再堆叠 |
| 优先级竞争分裂 | 设置明确的 Master 优先级 |
| 未配 MAD 脑裂 | 配置 MAD 检测与业务口关闭策略 |
| 堆叠口配置错误 | 核对堆叠口物理口与逻辑口配置 |

## 注意事项
堆叠最怕"分裂"：分裂瞬间两台设备各自抢占网关（VRRP/ARP），业务会短时中断甚至双主；务必配置 MAD 并在割接窗口内处理。
