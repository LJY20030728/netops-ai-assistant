# DNS 域名解析故障排查

## 问题现象
终端能 ping 通 IP 但打不开网页/访问不了域名；部分域名能解析、部分不能；解析结果错误或超时。

## 排查步骤
1. 确认终端 DNS 配置：
   - Windows：`ipconfig /all` 查看 DNS 服务器；
   - 终端 DNS 指向错误（如指向已下线服务器）是最常见原因。

2. 验证解析过程：
   ```
   nslookup <域名>
   nslookup <域名> <指定DNS服务器>
   ```
   - 用公共 DNS（如 223.5.5.5、8.8.8.8）对比，能解析 = 内网 DNS 问题，不能 = 公网/域名问题；
   - 解析超时 = DNS 服务器不可达或防火墙拦截 UDP/TCP 53。

3. 检查 DNS 服务器侧：
   ```
   display dns server
   display logbuffer | include DNS
   ```
   - 服务器到上游 DNS（转发器/根）是否可达；
   - DNS 服务的递归查询是否被限制。

4. 检查域名与解析记录：
   - 域名是否过期/被暂停；
   - 解析记录是否正确（A/CNAME/MX），TTL 是否过短导致缓存频繁失效。

5. 检查网络策略：
   - 防火墙是否放行 DNS 流量（UDP 53，TCP 53 用于大报文）；
   - 是否配置了 DNS 重定向/劫持（行为管理设备）。

## 常见根因与处置
| 根因 | 处置 |
|---|---|
| 终端 DNS 指向错误 | 改为 DHCP 下发正确 DNS |
| DNS 服务器不可达 | 检查服务器状态与防火墙放行 53 |
| 上游解析失败 | 检查转发器配置与出口连通性 |
| 域名/记录问题 | 联系域名管理员修正记录 |
| DNS 劫持/污染 | 检查行为管理策略，启用 DoH |

## 注意事项
排障口诀：先看终端 DNS 配没配对，再用 nslookup 指定服务器对比，最后查服务器与防火墙；解析与连通是两件事，分开验证。
