# 防火墙双机热备 HRP 故障排查

## 问题现象
防火墙主备双机切换后业务中断、会话不保持；两台防火墙状态不一致（一台 Active 一台 Standby 异常）；心跳异常导致反复切换。

## 排查步骤
1. 查看双机状态：
   ```
   display hrp state
   display hrp interface
   ```
   - 正常：一台 Active、一台 Standby；
   - 两台都 Active = 心跳断开导致"双主"，流量会走两侧防火墙不一致。

2. 检查心跳链路：
   - HRP 心跳报文（UDP 694 或专用心跳口）是否被策略阻断；
   - 心跳口要配置为信任区域并放行 HRP 协议；
   - 心跳口不建议与业务口共用（业务洪峰会干扰心跳）。

3. 检查会话备份：
   ```
   display hrp session
   ```
   - 主设备上的会话是否实时备份到备机；
   - 备机学习到的会话数量是否与主机一致（数量明显少 = 备份失败）。

4. 检查配置一致性：
   - 主备防火墙的接口/区域/策略/NAT 配置必须一致；
   - 配置同步（hrp mirror）是否开启、是否有配置漂移。

5. 检查跟踪与倒换条件：
   - 跟踪的接口/链路 down 是否会触发倒换；
   - 倒换延迟配置是否合理，避免抖动误切换。

## 常见根因与处置
| 根因 | 处置 |
|---|---|
| 心跳中断双主 | 恢复心跳链路，放行 HRP 报文 |
| 会话备份失败 | 检查会话备份使能与数量 |
| 配置不一致 | 全量同步主备配置 |
| 跟踪误触发 | 调整跟踪接口与延迟 |
| 版本不一致 | 升级到一致版本 |

## 注意事项
双机热备排障核心是"状态、心跳、会话"三查：先看谁 Active，再看心跳通不通，最后看会话备没备份；双主是最危险的场景，优先处理。
