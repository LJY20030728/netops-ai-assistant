# 防火墙安全策略与会话表排查

## 问题现象
业务流量经过防火墙后不通（ping 不通、端口拒绝），但防火墙两侧设备各自可达；部分用户通、部分不通；策略命中计数异常。

## 排查步骤
1. 确认流量路径：
   ```
   display firewall session table
   display firewall session table verbose
   ```
   - 会话表里有没有这条流？没有 = 流量没到达防火墙或没命中策略；
   - 有会话但丢包 = 会话状态/老化问题。

2. 检查安全策略命中：
   ```
   display security-policy rule all
   display security-policy statistics
   ```
   - 源/目的安全区域（Zone）、地址、服务、动作（permit/deny）是否匹配；
   - 策略命中计数不增长 = 流量路径与策略不匹配。

3. 检查区域与接口归属：
   - 接口是否正确划分到安全区域（trust/untrust/dmz）；
   - 区域间默认动作（华为默认 deny）会拦截未放行流量。

4. 检查 NAT 与会话联动：
   - 源 NAT/目的 NAT 与安全策略的先后关系；
   - 会话表项老化时间过短导致长连接中断（大流量/长连接场景）。

5. 查看日志与攻击防护：
   ```
   display logbuffer | include SEC|FIREWALL
   display anti-attack statistics
   ```
   - 防火墙攻击防范（如 SYN flood 防护）误伤正常流量。

## 常见根因与处置
| 根因 | 处置 |
|---|---|
| 区域间策略缺失/deny | 补 permit 策略，最小化放行 |
| 接口区域划分错误 | 修正接口 Zone 归属 |
| 服务对象不匹配 | 核对目的端口/协议对象 |
| NAT 与策略顺序问题 | 调整 NAT/策略优先级 |
| 攻击防范误伤 | 调整阈值或加白名单 |

## 注意事项
防火墙排障顺序：会话表（流量到没到）→ 策略统计（命没命中）→ 区域归属（路径对不对）→ 日志（被谁拦的）；会话表是第一步，不要跳过。
