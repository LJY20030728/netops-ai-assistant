# VRRP 网关冗余故障排查

## 问题现象
终端网关（虚拟 IP）ping 不通或时通时断；主备切换后业务中断；两台设备同时是 Master 或同时是 Backup；负载均衡 VRRP 下流量异常。

## 排查步骤
1. 查看 VRRP 状态：
   ```
   display vrrp
   display vrrp verbose
   ```
   - 正常应是一台 Master、一台 Backup，虚拟 IP 由 Master 承担；
   - 两台都 Master = 分裂（心跳丢失）；两台都 Backup = 优先级/抢占配置问题。

2. 检查 VRRP 报文互通：
   - VRRP 组播报文（224.0.0.18）是否被 ACL/防火墙过滤；
   - 心跳接口之间的三层可达性（ping 对端接口地址）。

3. 检查优先级与抢占：
   - 优先级相同会都处于 Equal 状态，导致行为异常；
   - 抢占延迟（preempt-mode timer delay）配置不当会频繁切换。

4. 检查虚拟 IP 与业务接口：
   - 虚拟 IP 是否与真实接口同网段；
   - 跟踪功能（track/bfd）误触发导致频繁主备切换。

5. 查看日志确认切换原因：
   ```
   display logbuffer | include VRRP
   ```

## 常见根因与处置
| 根因 | 处置 |
|---|---|
| 心跳被过滤/断开 | 放行 VRRP 组播，恢复心跳链路 |
| 优先级配置不当 | 统一主备优先级与抢占策略 |
| track/bfd 误触发 | 检查跟踪的上行链路与阈值 |
| 两台都是 Master | 检查心跳与接口状态，确认配置 |
| 虚拟 IP 冲突 | 核对与真实接口网段一致性 |

## 注意事项
VRRP 排障三看：看状态（谁 Master）、看心跳（报文通不通）、看切换原因（日志）；主备切换后要观察业务是否随虚拟 IP 正常迁移。
