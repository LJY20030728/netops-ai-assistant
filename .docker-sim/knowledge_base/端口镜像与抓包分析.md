# 端口镜像与抓包分析

## 问题现象
需要抓包定位故障（应用延迟、协议交互异常、攻击定位），但设备没有 SPAN 口/镜像未生效，抓到的是空包或重复包。

## 排查步骤
1. 确认镜像配置：
   ```
   display observe-port
   display port-mirroring
   ```
   - 观察口（observe-port）是否指定、方向（inbound/outbound/both）是否正确；
   - 镜像源是端口（port-mirroring）还是 VLAN（vlan-mirroring）。

2. 检查镜像方向：
   - 只镜像 inbound 会漏掉出向流量；
   - 排障一般用 both 方向；关注源端口收发两侧。

3. 检查观察口连通性：
   - 抓包机要接在观察口上，观察口不能参与业务转发；
   - 观察口带宽要大于镜像流量总和，否则会丢包。

4. 检查多端口镜像与负载：
   - 多个源端口镜像到同一观察口时总流量不能超过观察口带宽；
   - 远程镜像（RSPAN/ERSPAN）检查隧道封装与目的可达。

5. 抓包分析要点：
   - 过滤条件（源/目的 IP、端口、协议）；
   - 关注 TCP 重传、乱序、窗口满；ICMP 超时；ARP 应答是否被抢答。

## 常见根因与处置
| 根因 | 处置 |
|---|---|
| 镜像方向配错 | 改为 both 或按需调整 |
| 观察口带宽不足 | 扩容观察口或减少镜像源 |
| 观察口参与业务 | 观察口隔离，仅接抓包机 |
| 远程镜像隧道不通 | 检查 RSPAN/ERSPAN 网络 |
| 抓包机接错口 | 核对观察口与抓包机网口 |

## 注意事项
抓包是"眼见为实"的最后手段：抓包前先想清楚要验证的假设（比如怀疑 ARP 欺骗就抓 ARP 报文），用精确过滤条件，避免大海捞针。
