# 路由重分发与路由优先级排障

## 问题现象
多协议环境（OSPF + 静态 + BGP）下，部分路由在协议间不传递、传递后路径与预期不一致，或出现路由环路。

## 排查步骤
1. 确认重分发配置：
   ```
   display current-configuration | include import|redistribute
   display ospf routing
   display bgp routing-table
   ```
   - 华为 OSPF 用 `import-route`，BGP 用 `import-route`/`network`；
   - 重分发时要带上 tag（路由标记），便于后续策略识别。

2. 检查被重分发的路由是否进了目标协议：
   - 源协议里有的路由，目标协议表里没有 = 重分发没生效或被过滤；
   - 检查 route-policy 是否把重分发路由过滤掉。

3. 检查环路防护：
   - 多协议互导且无防环机制（tag + route-policy）时，路由可能来回重分发形成环路；
   - OSPF 中 `import-route` 后要确认没有把外部路由再导回源协议。

4. 检查优先级与选路：
   ```
   display ip routing-table protocol ospf
   display ip routing-table protocol static
   ```
   - 同一前缀多来源时按 preference 选路（华为默认：直连 0、静态 60、OSPF 10、BGP 255）；
   - 可通过 `preference` 调整协议优先级实现路径偏好。

5. 验证端到端路径：
   ```
   tracert <目的地址>
   ```

## 常见根因与处置
| 根因 | 处置 |
|---|---|
| 重分发未配置/方向错 | 在正确协议下配置 import-route |
| 被 route-policy 过滤 | 检查策略，放行必要前缀并打 tag |
| 多协议互导成环 | 增加 tag + 防环策略，单向重分发 |
| 优先级不符合预期 | 调整 preference 或修改路由协议设计 |
| 外部路由类型开销大 | 检查 type-1/type-2 外部路由开销计算 |

## 注意事项
多协议重分发是环路高危区，任何"路由消失/绕路"先看协议表项与 tag，再动策略；改动前备份 route-policy。
