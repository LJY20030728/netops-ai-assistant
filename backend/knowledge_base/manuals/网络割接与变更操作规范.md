# 网络割接与变更操作规范

## 问题现象
网络改造（换设备、改路由、升级链路）过程中或之后业务中断；变更窗口内出现问题无法快速回退；多步骤割接缺少checklist。

## 排查步骤
1. 割接前准备：
   - 现状盘点：拓扑、IP 规划、路由协议、ACL、NAT 全量梳理；
   - 配置备份：所有涉及设备 save + 导出配置文件；
   - 风险评估：列出受影响业务、依赖关系、单点风险。

2. 制定割接方案：
   - 明确时间窗口（业务低峰）、操作步骤、每步验证点；
   - 制定回退方案：每个步骤都有对应的回退动作；
   - 准备验证清单：业务连通性、路由表、协议邻居、告警。

3. 割接执行纪律：
   - 一次只改一个变量，改完立即验证；
   - 使用配置预演（display this 对比）确认无意外修改；
   - 超时/异常立即停止，按预案回退，不恋战。

4. 割接后验证：
   - 业务级验证（用户实际访问）优先于技术指标；
   - 观察告警平台 24-48 小时，确认无隐藏问题；
   - 更新文档（拓扑图、IP 台账、配置基线）。

5. 变更管理工具：
   - 变更单（变更内容/影响/审批/回退）；
   - 维护窗口制度、变更评审会。

## 常见风险与处置
| 风险 | 处置 |
|---|---|
| 方案不完整 | 全量盘点现状，评审方案 |
| 无回退预案 | 每步明确回退动作 |
| 一次改太多 | 拆小步，逐步验证 |
| 验证不充分 | 业务级验证 + 观察期 |
| 文档不同步 | 割接后立即更新台账 |

## 注意事项
割接的最高原则是"可回退、可验证、窗口内不恋战"；宁可延迟交付，不要带着未验证的变更过夜。
