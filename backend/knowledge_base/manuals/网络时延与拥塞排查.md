# 网络时延与拥塞排查

【故障关键词】时延、拥塞、延迟高、卡顿、带宽打满、丢包、TCP 重传


## 问题现象
业务访问卡顿、视频会议花屏/音画不同步、数据库/交易类应用响应慢；ping 时延抖动大（忽高忽低）或持续高位。

## 排查步骤
1. 量化时延与抖动：
   ```
   ping -c 100 <目标>
   tracert <目标>
   ```
   - 看 avg 与抖动（min/max 差距）、丢包率；
   - tracert 逐跳看时延在哪一跳开始变大（确定瓶颈段）。

2. 检查链路带宽利用率：
   ```
   display interface <端口>
   display qos statistics interface
   ```
   - 利用率持续 >70% 时排队时延会显著上升；
   - 出方向拥塞（Output 队列丢弃）是时延高的直接原因。

3. 检查队列与 QoS：
   - 是否配置 QoS 队列调度（PQ/WFQ/CBQ），关键业务是否被普通流量挤占；
   - 突发流量（备份、批量任务）是否占满带宽。

4. 检查设备转发性能：
   ```
   display cpu-usage
   display memory-usage
   ```
   - 设备 CPU/内存高会影响转发（尤其防火墙/中低端交换机）；
   - 策略/ACL 过多增加转发开销。

5. 检查链路质量（长时延高抖动）：
   - 跨运营商/跨境链路的固有 RTT；
   - 无线链路（微波/卫星）的波动特性；
   - 光纤链路误码（CRC 增长）导致重传。

## 常见根因与处置
| 根因 | 处置 |
|---|---|
| 带宽拥塞 | 扩容链路或启用 QoS 保障关键业务 |
| 队列配置缺失 | 配置 PQ/CBQ，关键业务高优先级 |
| 设备性能瓶颈 | 优化策略数量、升级设备 |
| 链路误码 | 更换光模块/线缆，清洁端面 |
| 长距离 RTT | 优化应用架构，引入缓存/CDN |

## 注意事项
时延排障先量化（哪一跳、多大、抖不抖），再查拥塞（利用率/队列），最后查链路质量（误码/距离）；"时延高"要先分清是传播时延、排队时延还是处理时延。
