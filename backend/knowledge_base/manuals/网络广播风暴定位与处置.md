# 网络广播风暴定位与处置

## 问题现象
交换机接口广播/组播计数暴涨、接口利用率高、CPU 高，全网或部分 VLAN 内终端上网极慢甚至瘫痪；关掉某端口后恢复。

## 排查步骤
1. 确认风暴现象：
   ```
   display interface brief
   display interface <端口>
   ```
   - 接口 Input 速率异常高、Broadcast/Multicast 计数持续增长；
   - 多个接口同时异常说明风暴在传播。

2. 定位风暴源端口：
   - 逐段拔线法：断开嫌疑端口，观察风暴是否消失；
   - 看风暴计数最高的端口（通常是接入风暴源的端口）。

3. 检查环路（广播风暴最常见原因）：
   ```
   display stp brief
   display stp topology-change
   ```
   - 环路导致广播帧无限复制；STP 拓扑变化频繁是强信号；
   - 环路也可能由"对端未开 STP"或"端口未参与 STP"引起。

4. 检查异常流量源：
   - 感染蠕虫/病毒的终端持续发包（大量广播/未知单播）；
   - 私接设备（家用路由、Hub）引入环路或额外广播域。

5. 处置与预防：
   ```
   display storm-control configuration
   ```
   - 开启广播/组播/未知单播风暴控制（storm-control）；
   - 开启 STP 并合理规划根桥/阻塞口。

## 常见根因与处置
| 根因 | 处置 |
|---|---|
| 二层环路 | 剪断环路、开启 STP、核对端口角色 |
| 病毒/异常终端 | 隔离端口，清除病毒源 |
| 私接设备 | 移除违规设备，启用端口安全 |
| 广播域过大 | VLAN 拆分缩小广播域 |
| 未开风暴抑制 | 配置 storm-control 阈值 |

## 注意事项
广播风暴"来得快去得也快"，定位要快：先看计数最高的端口，再逐段拔线确认，最后用 STP/风暴控制预防复发；风暴期间不要同时动多个端口，避免误判。
