# 静态路由与默认路由排障

【故障关键词】静态路由、默认路由、路由表、跨网段、下一跳、间歇性不通、时通时断

## 问题现象
部分网段可达、部分网段不可达；或只有缺省路由可达，明细路由不通；流量走向与预期不一致。

## 排查步骤
1. 查看路由表：
   ```
   display ip routing-table
   display ip routing-table <目的网段>
   ```
   - 确认目的网段是否有路由条目、下一跳是否正确、优先级与开销；
   - 没有条目 = 缺路由；有条目不生效 = 下一跳不可达或优先级问题。

2. 检查下一跳可达性：
   ```
   ping <下一跳地址>
   display ip interface brief
   ```
   - 下一跳接口 down 或地址错误时，静态路由不生效；
   - 下一跳必须与本地直连网段可达（或通过迭代路由）。

3. 检查路由优先级与负载：
   - 多条同前缀路由时，preference 小者优先（华为静态默认 60）；
   - 想负载分担需要等价路由（同优先级同开销），否则只有最优路由生效。

4. 检查黑洞与汇总：
   ```
   display current-configuration | include ip route-static
   ```
   - 指向 NULL0 的黑洞路由会把流量丢弃（用于防环，配置错误会误丢）；
   - 汇总路由与明细路由并存时，最长匹配优先。

5. 验证实际转发路径：
   ```
   tracert <目的地址>
   ```

## 常见根因与处置
| 根因 | 处置 |
|---|---|
| 缺目的网段路由 | 添加静态路由 ip route-static |
| 下一跳不可达 | 修复对端接口/地址，确认直连 |
| 优先级被其他协议抢占 | 调整 preference 或检查动态协议 |
| 黑洞/汇总配置错误 | 核对 NULL0 路由与汇总掩码 |
| 出接口配置错误 | 指定正确出接口与下一跳 |

## 注意事项
静态路由的"症状"是路由表里直接可见的，先看表再定位，比反复 ping 高效；修改后用 display ip routing-table 验证条目出现。
