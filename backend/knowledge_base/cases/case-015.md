# 案例015：上联带宽打满（P2P 下载占满出口）

【告警类型】LINK_CONGESTION
【来源】simulated（模拟工单，按常见故障模式编写）

## 工单现象
出口带宽持续打满，办公业务卡顿。用户反馈"网速慢，视频会议经常断"，监控显示上联端口利用率持续 95%+。

## 排查过程
1. `display interface`：上联端口输入/输出利用率接近 100%；
2. 镜像上联口抓包分析：大量 P2P 下载流量（某终端长时间占用）；
3. `display qos statistics`：队列溢出丢包增长；
4. 对 P2P 流量限速 + 业务 QoS 优先级保障后，带宽占用回落、业务恢复。

## 根因
个别终端 P2P 下载占满出口带宽，队列拥塞丢包导致业务卡顿。

## 处置
出口限速策略 + 业务 QoS 队列保障；上线流量审计，识别大流量终端纳入管控。
